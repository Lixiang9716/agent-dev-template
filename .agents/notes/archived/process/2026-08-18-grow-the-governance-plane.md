# Agent Note: grow the governance plane

Status: implemented

## Problem

The ten standing orders were compliance-shaped: they told an agent how to behave inside the governance plane, never that the plane itself is theirs to extend. Derived agents executed the rules, but nothing invited them to add gates, postmortems, or skills as their project's own history demanded.

## Decision

Standing order 11 states the plane is a floor, not a ceiling, with event-driven triggers: a recurring defect class earns a postmortem whose guardrail distills into a gate; a convention enforced by hand a third time becomes a skill; a prose promise that turns checkable is promoted to a gate; decisions earn notes; new facts pick a tier before landing. architecture.md's "Growing the plane" section owns the trigger table; budgets and one-home-per-fact bound the growth.

## Alternatives considered

Leaving growth implicit (rejected: the invitation must live in always-loaded context, or agents stay compliance-only); a dedicated grow-the-plane skill (deferred: the table fits a section; promote it when it outgrows one); onboarding-time guidance for first-time users (rejected: templates have no first-run moment — AGENTS.md is the always-on channel).

## Consequences

Rule 11 is the first addition after the founding ten — itself an instance of the growth doctrine it states. Future rule additions each owe a note and a bilingual update in the same change.
