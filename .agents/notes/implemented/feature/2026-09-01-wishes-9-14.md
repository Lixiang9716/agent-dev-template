# Agent Note: wishes 9–14 — decision guard, review dossier, skill drift, trends, noise, orphans

Status: implemented

## Problem

Six more wishes from the adopter. The decisions table — every project's
governance spine — was pure prose: duplicate ids, numbering gaps, and
alternative-less entries passed silently. Reviewers cold-started through
four manual commands to assemble what the code-review skill expects.
Skill texts referenced gov commands and flags that nothing verified, so a
rename silently expired the manuals agents read most literally.
`--json`'s duration_ms evaporated per run. Long sessions flooded the
note-presence advisory with untracked files. And orphan .i18n.yaml
records outlived both of their documents, uncounted forever.

## Decision

`gov verify-decisions` applies the verify-rubric pattern to decisions
(D28): ids unique and contiguous from the table's first entry (D0 or D1
starts both legal), every entry must record its options or rejected
alternatives (rule 3's spirit across documents), and orphans — decisions
no note references — are informational, not violations; this repository's
D0–D27 ran green on the first invocation, and a paths-scoped decisions
gate joined this repo's config (not the template: content is
project-specific, the D17 stance). `gov review --base <ref>` assembles
the four-section dossier (scope, in-scope notes with the rule-2 warning,
recall hits for the change's own keywords, rubric items — three sections
without a rubric); the code-review skill (live and shipped copies, kept
identical) now starts from the dossier. audit-notes extends its
command-existence check to `.agents/skills/**/*.md` with a flag registry
per command (universal -h/--help/-v/--version exempt; the registry covers
every command). `gov run` appends one JSON line per run to
.gov/history/gates.jsonl and `gov trend` reports per-gate p50 across the
window's halves, naming movers at ×1.5. (Originally an opt-in `--record`
flag — "runs stay stateless by default"; D29 flipped recording to the
default with `--no-record` as the opt-out, so `--record` no longer
exists.) note-presence gains `--staged` (index only, silent when
clean) and collapses long lists past five; verify-pairing reports
dangling records whose both sides are gone.

## Alternatives considered

- Orphan decisions as violations — rejected: a decision may legitimately
  precede the notes that cite it; informational is the honest strength.
- Deriving the flag registry from argparse at runtime — rejected: the
  parsers are built inside main(); a static table pinned by a self-test
  case is cheaper and drifts loudly.
- Recording history by default — rejected: statelessness is the default
  contract; --record is explicit consent.
- An ignore_untracked config knob — rejected: same knob-aversion as D26;
  --staged and collapse cover the real pain.

## Consequences

The spine, the review flow, the agent manuals, and the timeline of gate
health are all under mechanical watch now; the first run of
verify-decisions on this repository reported ten orphan decisions —
information the prose never surfaced. Skill texts must keep their gov
references real or hear about it, and the flag registry doubles as
living documentation of every command's surface.
