# Agent Note: presets — typed adoption bundles (machinery + agent-heavy)

Status: implemented

Date: 2026-09-05
Related: D53, D28, D29, D39, D49, D51, D52

## Problem

`gov init` injects one set of generic gates: typed content varies by
project and stays out of the default template (D28). An adopter whose
project type needs a coherent starting set — a decisions-table guard plus
a worker-protocol skill plus a bookkeeping exemption, say — could only
hand-write `gates.json` and copy skills out of site-packages. Each of the
three content kinds already had a mature "land additively, never
overwrite local customizations" machine (D39 gate merge, D29 byte
adoption, D49 absent-key manifest hints), but nothing packaged them for
distribution with the plane.

## Decision

Shipped presets: declarative patch bundles at
`gov/templates/presets/<name>/` with a strict closed-key schema
(`preset.json`: name, description, gates, modes, skills, hints), and the
`gov preset list|show|apply` machinery plus `gov init --preset <name>`.
Apply reuses the existing adoption contracts — no new merge semantics:
gate fragments merge through D39's by-id semantics (extracted from
`init --adopt-new` into the shared `gates.merge_gates_by_id`; --adopt-new
behavior is unchanged and its tests stayed green), with the preset
ruling "keep the local same-id gate and name the difference" where
--adopt-new refuses non-additive drift; skills copy byte-for-byte,
create-if-missing (D29); hints write only manifest keys that are absent
(D49). Apply is idempotent — a re-apply reports "already adopted"
everywhere, exits 0, and writes nothing; adopting into an uninitialized
project exits 2 naming `gov init`. The first built-in preset,
`agent-heavy`, packages the multi-agent parallel workflow validated in
the D51/D52 concurrency drills: the `verify-decisions` gate in the
`governance` mode, the `parallel-workers` skill (lease → verify →
preflight → blind coordination; also live at
`.agents/skills/parallel-workers/SKILL.md` under a D19-style
byte-equality test — this repo runs the same protocol), and
`note_presence_exempt: [".gov/tasks/**"]` (#149). `python-lib` and
`docs-bilingual` follow on the same matrix.

## Alternatives considered

Typed gates straight into the default template — rejected in D28 and
still wrong: the generic floor keeps every project from paying for gates
it will not use, and mode-based parking would degenerate back into
delete-the-definition. A preset registry / remote sources — rejected:
zero dependencies is a locked stance, and a preset lands gate `command`
argvs, so a remote preset is an arbitrary-command-execution surface;
bundled presets travel with code review. Overwriting local
customizations on apply — the exact inversion of D8/D39: the entire
value of a patch bundle is landing on top of what already exists.
An interactive wizard — rejected: agents are the primary users; flags
compose in scripts and CI, prompts do not. A general "merge-semantics
registry" (pluggable mergers per artifact) — YAGNI: exactly one merge
semantics exists today (D39's id identity); a registry for an imagined
second one is complexity futures.
