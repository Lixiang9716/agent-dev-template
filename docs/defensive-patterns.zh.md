# 防御模式

[English](defensive-patterns.md) | 中文

记录那些真实发生过、且重新发现代价高昂的缺陷类规则。每条陈述规则本身与它预防的 bug 类。只有带着促成它的失败才允许新增模式——没有伤疤的模式是投机。

## exit 与 signal 作为独立事实报告

子进程可能死于信号,从而永远不会产生正常的退出码。两个调度器移植都从原始等待状态推导两个事实——`exit N`,或状态超过 128 时的 `signal SIGKILL`(名字经 `kill -l` 得到)——并各自独立报告实际发生的那种。绝不把一个事实折叠进另一个的分支,否则被杀死的门禁会被读成干净的成功。这一分离由两侧调度器的 kill -9 测试钉住。

## Bash 函数内的声明是局部的

函数内的 `declare`(以及 `declare -A`)创建的是局部变量,返回即消失。调度器的结果映射正是这样消失的:`run_gates` 填充了它们,调用方读到未绑定变量并崩溃。跨函数状态需要 `declare -gA`。

## 持久的控制字符 IFS 毁掉带引号的数组展开

在 bash 5.1 上,IFS 留为控制字符会让每个带引号的 `"${arr[@]}"` 展开爆炸成单个字符——调度器以空 id 启动门禁,死在数组下标上。特殊 IFS 只作用于需要它的那一条命令(`IFS=$US read -ra ...`);绝不让它活过那一行。
